## 2. 판정 규칙 — 두 층을 섞지 않는다

우리 시스템은 출력이 확률적이라 "맞다/틀리다"로만 판정하면 싸움이 난다.
그래서 **동작 여부**와 **품질**을 아예 다른 칸에 적는다.

| 층 | 무엇을 보나 | 어떻게 적나 |
|---|---|---|
| **동작했나** | 응답이 왔나, 파일이 생겼나, 시간 내에 끝났나 | **P / F / B** (Pass / Fail / Blocked) |
| **잘했나** | 정밀도, 재현율, 응답시간, 음성 자연스러움 | **숫자로 기록.** 합불로 뭉개지 않는다 |

예: OCR이 "갈비탕"을 "갈비탕"으로 읽고 매칭까지 성공 → 동작 P, 품질 정밀도 집계에 +1.
OCR이 글자를 놓쳤지만 API는 200으로 정상 응답 → **동작 P, 품질은 재현율 하락으로 기록.**
이 둘을 한 칸에 넣으면 "이게 Fail이냐 아니냐"로 시간을 다 쓰게 된다.

- **Blocked(B)** 는 "우리 잘못이 아니라 못 돌린 것"이다. 서버가 죽어 있거나, 준비물이 없어서
  실행 자체를 못 한 경우. Fail과 반드시 구별해서 적는다.

## 3. 커버리지 점수판

각 영역에 **수동으로 실행했으면 1점, pytest로 자동화돼 있으면 +1점**.
**최종 점수 = 6개 영역 중 가장 낮은 점수.**

| 영역 | 수동 실행 | 자동화 | 소계 |
|---|---|---|---|
| A. OCR·매칭 | ⬜ | ⬜ | /2 |
| B. 나레이션 | ⬜ | ⬜ | /2 |
| C. TTS | ⬜ | ⬜ | /2 |
| D. 장바구니 | ⬜ | ⬜ | /2 |
| E. E2E | ⬜ | ⬜ | /2 |
| F. 배포·운영 | ⬜ | ⬜ | /2 |
| **최종 (최솟값)** | | | **/2** |

> 왜 평균이 아니라 최솟값인가: 평균을 쓰면 "OCR은 완벽한데 배포는 아무도 안 봤다"가
> 좋은 점수 뒤에 숨는다. 최솟값을 쓰면 **방치된 영역이 곧 팀 점수**가 되어서,
> 분담 후 비어 있는 칸이 바로 드러난다.
>
> (Google의 ML Test Score 채점 규칙에서 가져왔다. 항목은 재학습하는 시스템 전제라
> 우리와 안 맞아서 쓰지 않고, 채점 방식만 빌렸다.)

## 4. 결함을 발견하면

각 영역 파일 아래쪽 "발견한 결함" 표에 적는다. 심각도는 세 단계만 쓴다.

| 심각도 | 뜻 |
|---|---|
| **High** | 시연이 멈춘다. 사용자가 아무것도 못 한다 |
| **Mid** | 결과가 틀리지만 진행은 된다 |
| **Low** | 거슬리지만 기능에는 지장 없다 |

**성공한 케이스만 적지 않는다.** 실패를 적지 않으면 이 문서를 만들 이유가 없다.

## 5. 진행 순서

1. 위 배정표의 `담당` 칸에 이름을 적는다
2. 자기 영역 파일을 열고, 준비물을 확인한다
3. 타임박스를 재면서 케이스를 실행하고 **실측 결과 칸을 채운다**
4. 결함을 발견하면 아래 표에 적는다 (실패도 반드시 적는다)
5. 자기 파일만 커밋해서 PR을 올린다
6. 전원 완료되면 이 README의 점수판을 채운다
