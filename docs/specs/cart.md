# Spec — 장바구니 (Cart)

## Why

- **페르소나**: 한국어를 못 읽는 여행자. 식당에서 메뉴판 사진을 찍어 이 앱으로 확인 중이다.
- **상황**: 안내를 읽고 마음에 든 메뉴 두세 개를 골라, 종업원에게 "이거, 이거, 이거 주세요"라고 전하고 싶다.
- **문제**:
  1. 고른 메뉴를 기억해둘 곳이 없어서 후보 목록을 계속 오르내려야 한다.
  2. 같은 메뉴를 2인분 주문하고 싶을 때 수량을 표시할 방법이 없다.
  3. 메뉴판 가격을 읽어주긴 하지만(`price_krw`), 합계를 알 수 없어 예산을 못 가늠한다.
- **측정 지표**: 후보 화면 ↔ 결과 화면 왕복 횟수 감소, 주문 전 총액을 확인할 수 있는 비율.

## Goal

- **해결 목표**: 후보 화면에서 메뉴를 담고 수량을 조절하면, 담긴 목록과 원화 총계를 한곳에서 볼 수 있다.
- **성공 기준**
  - +/− 를 누른 뒤 화면의 카트 상태가 응답 1회로 갱신된다(부분 갱신 조합 없음).
  - 같은 음식은 항상 한 줄이다 (`food_id` 기준).
  - 수량은 절대 음수가 되지 않는다. 0이 되는 순간 그 줄은 사라진다.
  - 총계 = 담긴 각 줄의 `price_krw × quantity` 합.
- **Out of Scope**: 결제, **식당으로의 주문 전송**, 로그인 계정 연동, 카트 영속 저장(서버 재시작 시 유지), 여러 기기 간 동기화, 메뉴 옵션(맵기 단계 등) 선택.

> 주문 확인 화면은 **여행자가 종업원에게 보여주는 요약 화면**이다. 어디에도 주문을 보내지
> 않는다. 그래서 "주문이 접수되었습니다" 같은 문구를 쓰지 않는다 — 실제로 접수되지 않았는데
> 접수된 것처럼 보이면 여행자가 자리에 앉아 음식을 기다리게 된다.

## What

**Happy Path**
1. 메뉴판 사진 분석 → 후보 화면에 메뉴 카드 목록이 뜬다.
2. 카드의 음식 이름 옆 `+` 를 누른다 → 서버가 카트에 담고 **카트 전체 상태**를 돌려준다.
3. 화면 아래 장바구니 섹션에 그 메뉴가 한 줄로 나타나고, 총계가 갱신된다.
4. 같은 메뉴의 `+` 를 또 누르면 새 줄이 생기지 않고 기존 줄의 수량이 2가 된다.
5. `−` 를 눌러 수량이 0이 되면 그 줄이 목록에서 사라지고 총계에서 빠진다.
6. `Order` 를 누르면 주문 확인 화면으로 넘어간다 — 담은 메뉴를 **한글 이름 위주로** 크게
   보여줘서 종업원이 읽을 수 있게 한다. 카트는 그대로 남는다(보여주고 돌아와 고칠 수 있어야 한다).
7. `Clear cart` 를 누르면 카트를 비운다.

**Edge Cases**

| # | 상황 | 처리 방식 |
|---|---|---|
| EC-01 | 수량 1에서 `−` 를 누름 | 0 → 줄 자동 삭제. 음수로 내려가지 않는다 |
| EC-02 | 카트에 없는 메뉴에 `−` 를 누름 | 아무 일도 없음(no-op). 수량 0짜리 줄을 만들지 않는다 |
| EC-03 | 메뉴판에서 가격을 못 읽은 메뉴를 담음 | 담기는 된다. 총계에는 0으로 들어가고 `has_unpriced_items: true`로 "총계가 일부만 반영됨"을 알린다 |
| EC-04 | 같은 음식을 다른 사진에서 다시 담음 | 한 줄로 합친다. 이번에 읽은 가격이 있으면 그 값으로 갱신한다(없으면 기존 값 유지) |
| EC-05 | 처음 방문이라 카트가 없음 | 빈 카트(`items: []`, `total_krw: 0`)를 정상 응답으로 돌려준다. 404 아님 |
| EC-06 | 서버가 카트 요청에 실패 | 화면의 카트 상태를 그대로 두고 섹션에 오류 문구만 표시. 담긴 내용을 지우지 않는다 |
| EC-07 | 카트가 빈 상태에서 Order/Clear | 두 버튼 모두 비활성. 빈 주문 확인 화면으로 넘어가지 않는다 |
| EC-08 | 주문 확인 화면에서 뒤로 감 | 카트가 그대로 남아 있어 수량을 고치고 다시 볼 수 있다 |
| EC-09 | 새 메뉴판 사진을 성공적으로 분석 | 카트를 비운다 — 아래 "카트의 수명" 참고 |
| EC-10 | 사진을 다시 찍음(흐림·미지원으로 실패) | 카트를 **유지**한다. 실패한 시도는 새 식당이 아니다 |
| EC-11 | 같은 화면에서 새로고침 | 카트가 남아 있다. 카트 ID가 localStorage에 있고 서버가 그 ID로 내용을 들고 있다 |

## How

카트는 브라우저가 만든 **카트 ID**(UUID, localStorage 보관)로 구분한다. 로그인이 없는 서비스라
세션·계정 대신 쓰는 최소 식별자이며, 모든 카트 요청에 `X-Cart-Id` 헤더로 실어 보낸다.

**카트의 수명 — 브라우저가 아니라 "지금 이 식당"에 묶는다.**
카트 ID는 브라우저에 남지만, **새 메뉴판을 성공적으로 분석하면 카트를 비운다.** 이렇게 하지
않으면 카트가 브라우저에 묶여서, A식당에서 담아둔 메뉴가 B식당 메뉴판을 찍은 뒤에도 목록에
남는다. 지금 앉아 있는 식당에서 주문하려고 쓰는 화면이므로 섞이면 안 된다.

비우는 시점은 **분석 성공 시점 하나뿐이다.** OCR 실패·미지원 음식으로 되돌아온 경우는 새
식당이 아니라 실패한 시도이므로 카트를 건드리지 않는다 — 흐리게 찍어 다시 찍는 흔한 흐름에서
이미 담아둔 것을 잃지 않게 하기 위해서다.

서버는 카트를 메모리에만 들고 있으므로 **서버가 재시작되면 카트도 사라진다**(위 Out of Scope).

```
GET /api/cart
헤더: X-Cart-Id: string (필수)
응답 200: CartResponse

POST /api/cart/items
헤더: X-Cart-Id: string (필수)
요청 바디:
{
  "food_id":        int,
  "name_kr":        string,
  "name_en":        string,
  "price_krw":      int | null,   // 메뉴판 사진에서 읽은 값. 못 읽었으면 null
  "quantity_delta": int           // +1 / -1. 음수 허용(빼기), 결과 수량은 0 미만이 될 수 없다
}
응답 200: CartResponse

CartResponse (두 엔드포인트 공통 — 언제나 카트 전체 상태):
{
  "cart_id": string,
  "items": [
    {
      "food_id": int, "name_kr": string, "name_en": string,
      "price_krw": int | null, "price_krw_display": string | null,
      "quantity": int,
      "line_total_krw": int | null, "line_total_display": string | null
    }
  ],
  "item_count": int,             // 전체 수량 합 (줄 수 아님)
  "total_krw": int,
  "total_krw_display": string,   // "₩21,000"
  "has_unpriced_items": bool
}

DELETE /api/cart
헤더: X-Cart-Id: string (필수)
응답 200: CartResponse (비워진 상태)

응답 실패:
422 X-Cart-Id 헤더 누락
```

**모바일 앱에서의 차이 두 가지** (`mobile/`)

- 카트 ID를 localStorage 대신 **앱 실행 중 메모리에만** 둔다. 앱을 껐다 켜면 카트가 비는데, 서버도 카트를 메모리에만 들고 있어 재시작하면 사라지므로 같은 수준의 동작이다(위 Out of Scope). 그래서 EC-11("새로고침해도 남아 있다")은 앱에서 화면 전환에만 해당한다.
- 카드에서 상세 화면으로 가는 동작은 그대로 두고, `+`/`−` 는 카드 오른쪽 끝에 둔다. 카드 아무 데나 누르면 상세로 가고, 스테퍼를 누르면 담긴다.

- 저장소: 서버 프로세스 메모리(`dict`). 재시작하면 비워진다 — Out of Scope의 "영속 저장"에 해당.
- 줄 순서: 처음 담은 순서를 유지한다. 수량이 바뀌어도 자리를 옮기지 않는다.
- 금액 표기: `src/ocr/price.py`의 `format_price_krw()`를 그대로 쓴다(₩ + 천 단위 콤마).

## AC (Given-When-Then)

**AC-01 · 담으면 카트 전체 상태가 돌아온다**
- GIVEN: 빈 카트
- WHEN: `POST /api/cart/items` 로 비빔밥(9,000원) `quantity_delta: 1`
- THEN: 응답에 items 1줄(quantity 1), `item_count: 1`, `total_krw: 9000`, `total_krw_display: "₩9,000"`

**AC-02 · 같은 음식은 한 줄로 합쳐진다**
- GIVEN: 비빔밥 1개가 담긴 카트
- WHEN: 같은 `food_id`로 `quantity_delta: 1`
- THEN: items는 여전히 1줄, `quantity: 2`, `line_total_krw: 18000`

**AC-03 · 수량이 0이 되면 자동 삭제된다**
- GIVEN: 비빔밥 1개가 담긴 카트
- WHEN: `quantity_delta: -1`
- THEN: `items: []`, `item_count: 0`, `total_krw: 0`

**AC-04 · 음수 수량을 허용하지 않는다**
- GIVEN: 비빔밥 2개가 담긴 카트
- WHEN: `quantity_delta: -5`
- THEN: 줄이 삭제된다. 수량이 음수인 줄은 응답에 없다

**AC-05 · 가격을 못 읽은 메뉴는 총계에 0으로 들어간다**
- GIVEN: 빈 카트
- WHEN: `price_krw: null`인 메뉴를 담는다
- THEN: items에 1줄(`line_total_krw: null`), `total_krw: 0`, `has_unpriced_items: true`

**AC-06 · 총계는 모든 줄의 합이다**
- GIVEN: 빈 카트
- WHEN: 비빔밥(9,000) 2개 + 불고기(12,000) 1개를 담는다
- THEN: `total_krw: 30000`, `item_count: 3`

**AC-07 · 카드의 +/− 로 실시간 갱신된다 (프론트)**
- GIVEN: 후보 화면
- WHEN: 메뉴 이름 옆 `+` 를 누른다
- THEN: 응답의 카트 상태로 장바구니 섹션과 카드의 수량 표시가 함께 갱신된다. 수량 0에서 `−` 는 비활성이다

**AC-08 · 카트를 비운다**
- GIVEN: 메뉴 두 개가 담긴 카트
- WHEN: `DELETE /api/cart`
- THEN: `items: []`, `total_krw: 0`. 다른 카트 ID의 내용은 그대로다

**AC-09 · 주문 확인 화면은 카트를 건드리지 않는다 (프론트)**
- GIVEN: 메뉴가 담긴 카트
- WHEN: `Order` 를 누르고 주문 확인 화면에서 뒤로 돌아온다
- THEN: 카트 내용과 총계가 그대로다 (주문은 어디로도 전송되지 않는다)
