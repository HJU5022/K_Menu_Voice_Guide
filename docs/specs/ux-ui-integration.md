# UX/UI · React 프런트엔드 연동 Spec

> **문서 목적**: React/Vite 기반 K-Menu 프런트엔드가 메뉴 이미지 입력부터 음식 정보·음성 안내 확인까지 제공하는 사용자 경험과, 향후 Python 백엔드 API에 연결하기 위한 계약을 정의한다. 이 문서는 현재 구현된 화면과 후속 API 연동 범위를 구분한다.

## Why

- **페르소나**: 한국 음식과 한글 메뉴판에 익숙하지 않은 영어권 개별 관광객이다.
- **상황**: 사용자는 식당에서 메뉴판을 촬영하거나 업로드하고, 후보 음식 중 하나를 골라 재료·맵기·알레르기·먹는 법과 음성 안내를 확인하려 한다.
- **문제**:
  1. 사용자는 한글 메뉴판에서 음식명을 바로 이해하기 어렵고, 단순 번역만으로는 재료·알레르기·먹는 법을 판단하기 어렵다.
  2. 카메라 권한 거부, OCR 실패, 지원하지 않는 음식, 음성 생성 실패처럼 현장에서 자주 발생할 수 있는 상태를 이해하기 쉬운 화면으로 안내해야 한다.
  3. 프런트엔드는 API 호출 구조를 갖추고 있으나, 최신 Python 저장소에는 이 API 계층이 아직 구현되지 않았다. 따라서 화면 구현과 실제 OCR·TTS 연동을 분리해 관리해야 한다.
- **측정 지표**: 사용자가 이미지 입력, 후보 선택, 결과 확인, 재시도 행동을 각 상태에서 이해할 수 있는지 검증한다. 정상 연동 이후에는 이미지 분석 성공률, 후보 선택 완료율, 결과 화면 도달률을 측정한다.

## Goal

### 해결 목표

React/Vite 단일 페이지에서 카메라 촬영 또는 이미지 업로드를 받아 음식 후보를 보여 주고, 선택한 음식의 상세 안내와 음성 재생을 제공한다. 텍스트 정보는 음성 재생 가능 여부와 무관하게 확인할 수 있어야 한다.

### 성공 기준

| 구분 | 완료 기준 |
|---|---|
| 이미지 입력 | 카메라 촬영과 파일 업로드 중 하나로 메뉴 이미지를 제공할 수 있다. |
| 개인정보 동의 | 카메라·이미지 처리 동의가 없으면 촬영·업로드를 막고 안내한다. |
| 처리 상태 | 분석 중 `Reading your menu` 상태와 취소 행동을 제공한다. |
| 후보 선택 | 후보 음식의 한글명·영문명·매칭 점수를 표시하고 사용자가 하나를 선택할 수 있다. |
| 결과 정보 | 설명, 먹는 법, 재료, 알레르기, 발음, 맵기 정보를 한 결과 화면에서 확인할 수 있다. |
| 음성 안내 | 음성 URL이 있으면 재생 컨트롤을 제공하고, 없으면 텍스트 정보는 계속 표시한다. |
| 오류 처리 | 카메라 오류, OCR 실패, 미지원 음식, 서비스 오류에서 재시도 또는 새 이미지 입력 행동을 제공한다. |

### Out of Scope

- Gradio UI 또는 `K_Menu_Talk.py` 기반 화면 구현
- 다국어 콘텐츠의 실제 번역·언어 전환 적용. 현재 언어 선택 UI는 존재하지만 화면 콘텐츠를 바꾸지 않는다.
- 사용자 계정, 결과 저장·공유, 주문·결제·예약
- `src/api/` 백엔드 API 구현과 실제 OCR·TTS 통합
- 실제 OCR 좌표 기반 후보 박스. 현재 후보 박스는 데모용 위치 값이다.

## What

### 구현된 사용자 흐름

1. 사용자는 개인정보 선택 배너에서 이미지 처리 동의를 확인한다.
2. 사용자는 카메라를 켜고 사진을 촬영하거나 이미지 파일을 업로드한다.
3. 프런트엔드는 이미지를 API에 전송하고, 분석 중 상태를 보여 준다.
4. API가 후보 배열을 반환하면 원본 이미지, 후보 음식명, 매칭 점수를 보여 준다.
5. 사용자가 후보 하나를 선택하면 해당 음식의 상세 가이드를 조회한다.
6. 결과 화면에 여섯 정보 영역과 음성 안내 상태를 표시한다.
7. 오류 발생 시 오류 유형에 맞는 안내와 재시도 행동을 제공한다.

### 화면 상태

| 상태 | 화면 동작 | 사용자 행동 |
|---|---|---|
| `camera` | 카메라·업로드 입력, 동의, 개인정보·약관 안내 | 카메라 촬영 또는 파일 선택 |
| `processing` | 메뉴 읽기 진행 문구와 취소 버튼 | 분석 취소 |
| `candidates` | 원본 이미지·후보 목록·데모 OCR 박스 | 후보 음식 선택 또는 새 메뉴 촬영 |
| `result` | 상세 정보 카드·음성 재생 또는 음성 실패 안내 | 이전 후보로 이동 |
| `error` | OCR, 미지원 음식, 서비스 오류별 안내 | 재시도 또는 새 메뉴 촬영 |

### 결과 정보 기준

| API 응답 필드 | 화면 표시 |
|---|---|
| `foodKo`, `foodEn` | 음식 한글명·영문명 |
| `matchScore` | 후보 목록의 매칭 점수 |
| `description` | 음식 설명 |
| `howToEat` | 먹는 법 |
| `ingredient` | 주요 재료 |
| `allergy` | 알레르기 안내 — 강조 카드 |
| `pronunciation` | 발음 안내 |
| `spicy` | 맵기 정보 |
| `narrationText` | 음성 안내 원문 |
| `audioUrl` | 음성 재생 URL. 값이 없으면 텍스트 우선 상태 표시 |

## How

### 프런트엔드 구조

현재 프런트엔드는 `frontend/src/App.tsx`를 중심으로 구현되며, `LanguageSelector.tsx`와 `styles.css`를 사용한다. Vite 환경 변수 `VITE_API_BASE_URL`을 통해 API 주소를 설정하고, 값이 없을 때만 로컬 개발 기본값 `http://localhost:8000`을 사용한다.

```text
[Camera capture / Image upload]
              |
              v
[React App.tsx]
  | POST /api/menu/analyze
  v
[Future Python API layer]
  | OCR -> candidate response
  v
[Candidate selection]
  | GET /api/foods/{foodId}/guide
  v
[Result cards / Audio player]
```

### API 계약 — 후속 백엔드 구현 필요

| 요청 | 프런트엔드 기대 응답 | 현재 상태 |
|---|---|---|
| `POST /api/menu/analyze` | `{ candidates: FoodCandidate[] }` | 프런트엔드 호출 코드 구현됨, Python API 미구현 |
| `GET /api/foods/{foodId}/guide` | `FoodGuide` 객체 | 프런트엔드 호출 코드 구현됨, Python API 미구현 |

`FoodCandidate`는 `foodId`, `foodKo`, `foodEn`, `matchScore`를 포함한다. `FoodGuide`는 결과 정보 기준 표의 상세 필드를 포함한다. 실제 API를 구현할 때 이 필드명과 응답 형식을 맞추거나, 백엔드 계약 변경에 맞춰 프런트엔드를 함께 수정해야 한다.

### 환경·보안 제약

- `frontend/.env.example`에는 공개 가능한 `VITE_API_BASE_URL`만 기록한다.
- 실제 `frontend/.env`는 개발자 PC 또는 배포 환경에서만 생성하고 커밋하지 않는다.
- `VITE_*` 값은 브라우저 번들에 노출될 수 있으므로 API 키, Supabase 키, TTS 키, 비밀번호를 넣지 않는다.
- `node_modules/`, `dist/`, 로그, TypeScript 캐시는 `frontend/.gitignore`으로 제외한다.
- 화면의 이미지 비저장·오디오 스트리밍 안내 문구는 실제 백엔드 동작과 일치하는지 API 구현 시 다시 검토한다.

## AC (Given-When-Then)

**AC-01 · 이미지 처리 동의 확인**

- GIVEN: 사용자가 이미지 처리 동의를 해제했다.
- WHEN: 카메라 또는 업로드로 메뉴 이미지를 제공하려 한다.
- THEN: 이미지는 전송되지 않고 동의가 필요하다는 안내가 표시된다.

**AC-02 · 후보 목록 표시**

- GIVEN: 메뉴 분석 API가 하나 이상의 후보를 반환한다.
- WHEN: 프런트엔드가 응답을 수신한다.
- THEN: 원본 이미지와 후보의 한글명·영문명·매칭 점수가 표시되고, 사용자는 한 후보를 선택할 수 있다.

**AC-03 · 상세 가이드 표시**

- GIVEN: 사용자가 후보 음식을 선택하고 가이드 API가 정상 응답한다.
- WHEN: 프런트엔드가 `FoodGuide`를 수신한다.
- THEN: 설명, 먹는 법, 재료, 알레르기, 발음, 맵기 카드와 음성 상태가 표시된다.

**AC-04 · 음성 실패 시 텍스트 유지**

- GIVEN: 가이드 API 응답의 `audioUrl`이 비어 있다.
- WHEN: 결과 화면을 표시한다.
- THEN: 음성 이용 불가 안내를 표시하되 음식 상세 텍스트는 그대로 표시한다.

**AC-05 · 오류 재시도**

- GIVEN: 분석 또는 가이드 요청이 실패한다.
- WHEN: 프런트엔드가 오류를 처리한다.
- THEN: 내부 오류 정보는 노출하지 않고, 오류 유형별 안내와 재시도 또는 새 메뉴 촬영 행동을 제공한다.
