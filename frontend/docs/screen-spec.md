# Screen Specification

## Why

화면별 요소·문구·오류 행동을 미리 정리해 팀원이 같은 사용자 경험을 검토한다.

## Goal

모든 화면에 현재 상태와 다음 행동을 명확히 제공한다.

## What

| 화면 | 필수 요소 | 사용자 행동 |
|---|---|---|
| 랜딩 | 서비스 한 줄 설명, 이용 3단계(촬영 → 선택 → 듣기), 사진 사용 안내 | `Get started` |
| 촬영/업로드 | 촬영 안내, 카메라, 업로드 | `Take a photo`, `Upload a menu photo` |
| 분석 중 | 진행 문구, 단계 표시, 취소 | `Cancel` |
| 후보 선택 | 원본 메뉴 사진, 강조 영역, 후보 카드(수식어 태그 포함), 장바구니 | 음식 선택, 담기, `Back`(촬영으로) / `Start over`(첫 화면으로) |
| 음식 상세 | 음식명, **이름 옆 스피커**, 발음, 맵기, **나레이션 문장**, **가로 재생바**, 6개 정보 카드 | 이름 듣기, 설명 듣기, 목록으로 |
| 오류 | 쉬운 원인 설명, 회복 행동 | 재시도 또는 새 메뉴 스캔 |

상세 카드는 다음 순서로 제공한다.

1. Description
2. How to eat
3. Ingredients
4. Allergies & dietary needs
5. Pronunciation
6. Spice level

## How

**소리는 두 갈래로 나눈다** (2026-08-26). 이름 옆 스피커는 **이름만**, 아래 가로 재생바는
**설명 전체**를 재생한다. 서버가 각각 다른 파일로 준다(`name_audio_path` /
`narration_audio_path` — `docs/specs/api-layer.md`). 하나를 재생하면 다른 하나는 멈춘다.
겹쳐 나오면 둘 다 안 들린다.

- 생김새를 다르게 둔다. 둘이 비슷하면 이름만 듣고 싶은 사람이 설명을 통째로 재생한다.
- 재생 중에는 스피커 색이 바뀐다. 소리가 안 들리는 환경(음소거·이어폰)에서 눌렸는지조차
  모르면 계속 다시 누른다.
- 듣는 문장을 눈으로 따라갈 수 있게 **나레이션 원문을 화면에 싣는다.**

**첫 화면으로 가는 길을 눈에 보이게 둔다** (2026-08-26). 후보 화면의 `Back`은 촬영
화면으로 가고(다시 찍기), 첫 화면으로 가는 길은 머리말 로고뿐이라 눈에 띄지 않았다.
`Start over`를 나란히 둔다.

**카메라가 안 열리면 이유를 밝힌다** (2026-08-26). 예전에는 실패를 삼키고 조용히 파일
선택창을 열어서, 사용자에게는 "촬영을 눌렀더니 업로드 창이 뜬다"로만 보였다. 권한
거부·카메라 없음·미지원을 갈라 안내하고 "대신 사진 올리기"를 함께 준다.

**카트 줄은 서버와 같은 기준으로 식별한다** (2026-08-27). 서버는 카트 줄을
`(food_id, menu_text)`로 나눈다(`src/cart/store.py`의 `_line_key`). 그런데 화면은
`food_id` 하나만 봤다. 그래서 메뉴판에 따로 인쇄된 두 줄이 같은 음식이면(들깨칼국수 /
얼큰칼국수 → 둘 다 `칼국수`) 두 가지가 깨졌다.

- 한쪽을 담으면 **다른 카드의 수량도 같이 올랐다** — `quantityOf`가 먼저 찾은 줄을 돌려줬다.
- 카트·주문 목록의 React `key`가 겹쳐, **Clear 해도 첫 줄이 남았다.**

서버 응답으로 확인한 실제 모양(같은 `food_id`, 다른 `menu_text`):
```
food_id=18 qty=1 | '들깨칼국수 9,000'
food_id=18 qty=1 | '얼큰칼국수 8,000'
```

기준을 `lib/api.ts`의 `cartLineKey()` 한 곳에 두고 수량 조회와 두 목록의 key가 그것을 쓴다.
서버 규칙이 이미 정해져 있으므로 화면을 거기에 맞춘 것이다.

**좁은 폭에서 수량 고르개는 양끝으로 벌린다** (2026-08-27). 560px 아래에서
`.dish-actions`가 세로 배치로 바뀌며 `align-items:stretch`가 걸려, 고르개가 카드 폭만큼
늘어난다(버튼과 폭을 맞추려는 의도라 그대로 둔다). 그런데 안쪽 기본 정렬이 `flex-start`라
`−`·수량·`+` 셋이 왼쪽 끝에 뭉쳐 있었다 — 375px 실측에서 `+`가 오른쪽 끝에서 271px
떨어져 있었다. `.stepper`에 `justify-content:space-between`을 줘서 양끝에 붙인다.

- 서비스 설명은 랜딩이 혼자 맡는다. 같은 문구를 촬영 화면에 되풀이하지 않는다 — 시작 단추를 눌렀는데 제자리인 것처럼 읽힌다.
- 후보 화면은 사용자가 사진 속 글자와 후보를 직접 대조할 수 있어야 한다.
- 실제 OCR 좌표가 없는 임시 강조 영역은 예시임을 표시한다.
- 알레르기·식이 정보는 일반 카드보다 더 눈에 띄게 표시한다.
- 로딩 중에는 중복 전송을 막고 오류 화면에서는 회복 행동을 제공한다.

## AC (Given-When-Then)

- GIVEN: 후보 목록이 표시된다. WHEN: 사용자가 후보 카드를 선택하거나 가리킨다. THEN: 해당 메뉴 글자 영역을 강조한다.
- GIVEN: 알레르기 정보가 있다. WHEN: 상세 화면을 표시한다. THEN: 주의 스타일의 카드로 구분한다.
