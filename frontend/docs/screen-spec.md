# Screen Specification

## Why

화면별 요소·문구·오류 행동을 미리 정리해 팀원이 같은 사용자 경험을 검토한다.

## Goal

모든 화면에 현재 상태와 다음 행동을 명확히 제공한다.

## What

| 화면 | 필수 요소 | 사용자 행동 |
|---|---|---|
| 랜딩 | 서비스 한 줄 설명, 이용 3단계(촬영 → 선택 → 듣기), 사진 사용 안내 | `Get started` |
| 촬영/업로드 | 촬영 안내, 카메라, 업로드 | `Take a photo`, `Upload a menu photo` |
| 분석 중 | 진행 문구, 단계 표시, 취소 | `Cancel` |
| 후보 선택 | 원본 메뉴 사진, 강조 영역, 후보 카드 | 음식 선택, `Scan another menu` |
| 음식 상세 | 음식명, 발음, 맵기, 6개 정보 카드, 오디오 상태 | 다른 메뉴 스캔, 오디오 재시도 |
| 오류 | 쉬운 원인 설명, 회복 행동 | 재시도 또는 새 메뉴 스캔 |

상세 카드는 다음 순서로 제공한다.

1. Description
2. How to eat
3. Ingredients
4. Allergies & dietary needs
5. Pronunciation
6. Spice level

## How

- 서비스 설명은 랜딩이 혼자 맡는다. 같은 문구를 촬영 화면에 되풀이하지 않는다 — 시작 단추를 눌렀는데 제자리인 것처럼 읽힌다.
- 후보 화면은 사용자가 사진 속 글자와 후보를 직접 대조할 수 있어야 한다.
- 실제 OCR 좌표가 없는 임시 강조 영역은 예시임을 표시한다.
- 알레르기·식이 정보는 일반 카드보다 더 눈에 띄게 표시한다.
- 로딩 중에는 중복 전송을 막고 오류 화면에서는 회복 행동을 제공한다.

## AC (Given-When-Then)

- GIVEN: 후보 목록이 표시된다. WHEN: 사용자가 후보 카드를 선택하거나 가리킨다. THEN: 해당 메뉴 글자 영역을 강조한다.
- GIVEN: 알레르기 정보가 있다. WHEN: 상세 화면을 표시한다. THEN: 주의 스타일의 카드로 구분한다.
